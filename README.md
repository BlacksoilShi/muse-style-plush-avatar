# Muse-style Plush Avatar

**非官方灵感项目，与OpenAI、xAI、Meta/Muse无隶属、授权或背书关系，不提供官方角色资产。**

跨平台毛绒头像提示词与Agent Skill：统一独立圆角矩形织布脸、珠眼、笑口与腮红，同时保留完整头发、刘海、耳朵、配饰和服装。默认双参考分工：A管脸与构图，B管当前角色外观。

## 最快用法

1. 准备你有权使用的共同脸部母版A与当前主体图B。公开包不含私人参考图；上传文档也不会自动带入图片
2. 打开 [Grok说明](adapters/grok.md) 或 [Muse说明](adapters/muse.md)，按当前实际入口选择双图、单图或文字路径
3. 双图路径按A、B顺序上传，核对预览，只复制一条短提示并填写外观重点。其他平台见 [ChatGPT](adapters/chatgpt.md) 或 [通用说明](adapters/manual.md)
4. 先看脸、完整发型衣服饰物与无细颈承托；只针对出现的问题修一处，再检查透明文件

全部通用/英文提示与定向修正在 [prompts/avatar.md](prompts/avatar.md)。支持Skill的宿主按其产品流程加载SKILL.md；不支持或未核实安装时，直接用提示与独立参考图。Grok Build、Bot和Imagine是不同入口；Muse Agent与Muse Image模型也不能等同。

## 圆形透明收尾

Python 3.10+ 和 Pillow。无网络请求、无 API key。建议在虚拟环境运行：

```bash
python -m venv .venv
# macOS/Linux: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

先查看生成图的实际像素，测量圆心、半径和关键特征极值。下列是**仅适用于 64×64 合成测试图**的示例，不要把数字直接用于你的头像：

```bash
python scripts/finish_circle.py outputs/generated.png outputs/circle.png \
  --center 31.5 31.5 --radius 28 \
  --protect-point 31 10 --reviewed --qa-dir qa/run-001
```

真实图片请用自己的测量值替换，重复 `--protect-point X Y` 保护所有重要极值。点必须距离圆边至少 3 像素。`--reviewed` 是你已审核的声明，不是脚本替你做了视觉检查。

- RGBA 输入：只降低 alpha；内部 RGBA 与 RGB 保持不变
- RGB 输入：额外加 `--allow-rgb` 才能处理。RGB须不含透明色键元数据，给原本不透明的像素初始化 alpha=255 后再裁圆；RGB 指解码后像素，不保证 JPEG 文件字节不变
- 灰度、调色板、动画、有未归一化 EXIF 方向的图：拒绝。先另外准备规范图片并重审
- 圆边采用 4×4 子像素覆盖率，约 1 像素抗锯齿带；验证圆外指像素中心距圆心大于 radius+1 的区域
- 不改变画布大小、不重绘、不抠角色、不修白边、不使内部透明变实心、不自动估计圆心或保证保护点以外的特征安全
- 原图和已有输出不会覆盖，QA 必须使用新目录。QA 包含 `dark.png`、`light.png` 和 `verification.json`，均用于本地检查
- 输出重建自像素，避免携带源 EXIF；隐形 RGB 未清零是为了遵守 RGB 不变。不要把透明当成敏感信息擦除，公开前检查所有像素

## 测试与限制

单元测试使用合成图，不含照片和第三方素材。覆盖 alpha/RGB 不变性、圆外透明、保护点、非法几何、拒绝覆盖、RGB 显式转换、模式拒绝和 CLI。实际外部模型未运行；提示词的可移植性不等于视觉结果一致性。面板造型依赖逐张人工视觉检查，圆边脚本不会分类或保证脸部结构。

## 内圆不透明与外圈透明

这是可选、需宿主和用户允许本地圆边收尾的文件质量路径。若图像工具原生透明输出留下内圆半透明或孔洞，不能靠脚本增加旧RGBA透明度来掩盖：先用图像工具把已通过造型的成图编辑为真正不透明的浅蓝方形中间图，只改变背景／输出透明格式；再验证RGB无透明元数据或RGBA全部alpha255，最后用现有只降alpha蒙版裁圆。RGB用显式`--allow-rgb`。

背景编辑可能重新渲染纹理或延伸原圆外的身体，必须重新看实际最终圆图、重新标点和绑定新哈希。检查内圆alpha255／零孔洞、圈外0、仅抗锯齿带有部分alpha，并检查配件保护点和深浅底。最终Python步骤不改RGB，但这不等于此前模型编辑也保持RGB逐像素相同。没有这条路径权限／能力时披露原生输出限制，不改用未经允许的像素修补。公开包未进行各平台端到端验证，不能从该流程说明推断跨模型保证。
